"test" · SHADW Forge

Test the game where it cannot phone home

Put your headless test in shadw.game.json. Forge runs it in a throwaway copy with the network off, a timeout and an output cap, and records what happened.

built (G1)

What it does for a game

  • Copies the project without .git, .godot, .shadw and build output, and runs test.command there.
  • godot as the first word means the Godot binary in $SHADW_GODOT.
  • The test writes results to $SHADW_ARTIFACT_DIR; Forge hashes each file.
  • Every run lands in .shadw/runs/<id>/: manifest, result, events and artifacts.
  • shadw game timeline merges every run's events, checks each hash chain, and exits 1 on a broken one.

Not built yet

Isolation. Forge's local runner is a process with the network off, not a security boundary: it is for a studio's own code. Memory and CPU limits are not enforced yet. Running untrusted mods waits for Forge's escape test (decision G5). shadw game build (the Godot export) is still open in G1.
