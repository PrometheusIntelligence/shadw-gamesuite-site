SHADW Game Suite

One file. Four products. Two already work.

Your engine stays yours. shadw.game.json asks Terrain for the world, Forge for sandboxed bot tests, and later KeyForge for keys and shadw.cloud for servers.

What works today

Worlds from a seed

shadw game world asks SHADW Terrain for the map, writes it with a lock file, and builds a Godot scene with collision and spawn markers.

Terrain in the suite

Bot matches in a sandbox

shadw game test runs your headless test under SHADW Forge with the network off and records hashed artifacts and an event chain.

Forge in the suite

Three games already run it

Tidewatch (Godot, tactics), Shadow Duel (JavaScript, cards) and Brine & Brie: Shipwright (C# on Godot .NET, sailing).

Your engine stays your engine

The suite is not an engine. It holds only the thread between products: the project file, the CLI and, later, an engine plugin. Godot 4 is the first engine (open source, so headless servers run with no licence questions). Unity and others come after.

Honest about what is next

Keys and signed builds (G2), shipping to the mesh (G3), attacking your own game on staging (G4) and opening to outside studios (G5) are planned, not built. Each product page says what is missing.
